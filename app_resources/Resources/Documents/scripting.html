Make your own mathematical worlds

Writing fractals with AngelScript

A guided path from an empty file to a colorful, explorable fractal.

wxChaos scripts let you concentrate on the experiment: choose a formula, visit points, assign colors, and see what grows. You do not need to rebuild the application. A script is simply an AngelScript file with two small entry points, plus an optional orbit drawer when you want to reveal a point's journey.

Open the script editor Write the first fractal

The shape of every script

Configure() describes the fractal. Render() creates its pixels. DrawOrbit() is optional and traces the motion of a selected point. 

void Configure()
{
    SetFractalName("My first fractal");
    SetCategory("Complex");
}

void Render()
{
    // Your formula and pixel loops live here.
}

void DrawOrbit()
{
    // Optional: connect successive orbit points with DrawLine().
}

Save the file from the script editor and render the preview. When the script compiles successfully it can join the scripted fractals in the application menu. If you leave out DrawOrbit(), wxChaos simply disables the Show orbit command for that fractal.

First expedition: a Mandelbrot set

The classic Mandelbrot loop is a wonderful first script because every part has a visible purpose. Copy this into the editor, render it, and then change the power, bailout, or palette value to make it yours. 

void Configure()
{
    SetFractalName("My Mandelbrot");
    SetCategory("Complex");
    SetMinX(-2.5);
    SetMaxX(1.2);
    SetMinY(-1.2);
    SetDefaultIter(100);

    AddDoubleOption("bailout", "Bailout: ", 4.0);
}

void Render()
{
    const double bailout = GetDoubleOption("bailout");

    for (int y = ho; y < hf; y++)
    {
        const double cImaginary = maxY - y * yFactor;
        for (int x = wo; x < wf; x++)
        {
            const complex c(minX + x * xFactor, cImaginary);
            complex z(0.0, 0.0);
            bool inside = true;
            int n = 0;

            for (n = 0; n < maxIter; n++)
            {
                z = z * z + c;
                if (z.real() * z.real() + z.imag() * z.imag() > bailout)
                {
                    inside = false;
                    break;
                }
            }

            SetPoint(x, y, inside, n);
        }
    }
}

void DrawOrbit()
{
    const double bailout = GetDoubleOption("bailout");
    const complex c(orbitX, orbitY);
    complex z(0.0, 0.0);

    for (uint n = 0; n < maxIter; n++)
    {
        const complex previous = z;
        z = z * z + c;
        DrawLine(previous.real(), previous.imag(), z.real(), z.imag(), 0, 255, 0);

        if (z.real() * z.real() + z.imag() * z.imag() > bailout)
            break;
    }
}

Render it unchanged and visit the familiar boundary near ((-0.75, 0)).

Open Fractal options and try a larger bailout. Look for subtle changes in the exterior bands.

Replace z * z with pow(z, 3), widen the view, and meet the Multibrot set.

Configure the fractal before painting it

Configure() runs when wxChaos discovers the script. Use it to give the fractal a name, a useful starting view, and sensible behavior.

FunctionWhat it changes
SetFractalName(name)The name shown in the scripted fractal menu.
SetCategory(category)Places it under Complex, NumMet, Physic, or Other.
SetMinX, SetMaxX, SetMinYDefines the initial viewport. wxChaos calculates the top edge from the canvas aspect ratio.
SetDefaultIter(value)Chooses the initial maximum iteration count.
SetJuliaVariety(true)Enables the editable Julia constant exposed as kReal and kImaginary.
SetRedrawAlways(true)Requests a fresh render when the view changes. Useful for fractals that cannot be drawn partially such as the Gauss or Duffing maps.
SetExtColorMode(false)Disables the normal exterior-color behavior when the script is plotting its own geometry.
NoSetMap(true)Opts out of the usual set-map behavior for specialized scripts.
SetDocumentationPath(file)Connects the fractal to an HTML information page in Resources/Documents.

Give explorers a few knobs to turn

Options are not limited to names known by wxChaos. Your script invents each key. Declare options in Configure(), then read them once near the start of Render() or DrawOrbit(). The values appear automatically in Fractal options. 

void Configure()
{
    AddDoubleOption("a", "Feedback a: ", 2.75);
    AddIntegerOption("seed", "Seed: ", 12);
    AddBoolOption("mirror", "Mirror the orbit", true);
}

void Render()
{
    const double a = GetDoubleOption("a");
    const int seed = GetIntegerOption("seed");
    const bool mirror = GetBoolOption("mirror");

    // Use a, seed, and mirror in any formula you can imagine.
}

Keep option keys consistent and unique. Fetch them outside inner pixel loops: one lookup per render is clearer and cheaper than looking up the same value millions of times.

The canvas globals

wxChaos supplies the current view and the region assigned to this render worker as global variables.

GlobalsMeaning
minX, maxX, minY, maxYThe current viewport.
xFactor, yFactorMathematical distance represented by one pixel.
wo, wf, ho, hfHalf-open pixel bounds for this worker: loop from origin up to, but not including, final.
screenWidth, screenHeightThe canvas dimensions.
maxIterThe current maximum iteration count selected by the user.
paletteSizeThe number of colors available in the active palette.
threadIndexThe worker number. Use worker zero for algorithms that must run exactly one thread.
kReal, kImaginaryThe editable Julia constant when Julia variety is enabled.
orbitX, orbitYThe point selected for orbit drawing.
Why do the loops begin at ho and wo?

Pixel fractals are divided among render workers. Each worker receives a different rectangle, so respecting wo..wf and ho..hf prevents duplicated work. A single-orbit map such as Henon or Duffing is different: guard it with if (threadIndex == 0) so only one worker plots the orbit.

Turn mathematics into pixels and colors

The usual coordinate conversion is small enough to memorize:

double real = minX + x * xFactor;
double imaginary = maxY - y * yFactor;

int x = (real - minX) / xFactor;
int y = (maxY - imaginary) / yFactor;

Call SetPoint(x, y, insideSet, colorValue) to store a result. For an escape-time fractal, insideSet is normally true when the point never escaped, while colorValue is often the iteration count. For maps that visit isolated coordinates, check that the converted pixel lies inside the canvas before calling SetPoint().

Color is another playground. Try n, n * 3, an angle quadrant, or a distance transformed into the palette range.

Complex numbers and useful mathematics

The built-in complex type supports arithmetic, real(), imag(), and functions including pow, sqrt, sin, cos, tan, sinh, cosh, tanh, exp, log, and log10. Real-number versions carry an _r suffix, such as sin_r, pow_r, sqrt_r, abs_r, floor_r, and ceil_r. 

complex z(0.2, -0.4);
complex transformed = sin(z) + pow(z, 3);
double radius = sqrt_r(z.real() * z.real() + z.imag() * z.imag());

Make an orbit visible

In DrawOrbit(), start from orbitX and orbitY, apply the same recurrence used by the fractal, and connect each old point to the new one: 

void DrawOrbit()
{
    complex z(orbitX, orbitY);
    for (uint n = 0; n < maxIter; n++)
    {
        const complex previous = z;
        z = cos(z);
        DrawLine(previous.real(), previous.imag(), z.real(), z.imag(), 255, 180, 0);
    }
}

The final three arguments are red, green, and blue values from 0 to 255. Use green for convergence, red for escape, or invent a visual language that fits your experiment.

Borrow, remix, and wander

The directory app_resources/ScriptSamples/ contains compact starting points. They are meant to be read, copied, broken, and rebuilt:

  • Gradient.asThe smallest useful tour of palette values and SetPoint.
  • ScriptMandelbrot.asA complete escape-time pixel loop.
  • ScriptJulia.asUses kReal and kImaginary to expose a Julia family.
  • Henon.asPlots one long orbit instead of testing every pixel.
  • Escape_angle.asTurns the direction of escape into color structure.
  • hello_world.asExperiments with PrintString, PrintInt, PrintFloat, and PrintComplex.

The official scripts in app_resources/Scripts/ go further. Duffing demonstrates a custom option, while the Newton scripts combine options with orbit drawing. Start with a copy, change one idea, and let the resulting image tell you what to try next.

When the first render is not what you expected

  • Read the compiler row and column first; a missing semicolon often causes several later messages.
  • Check every array-like pixel access. Call SetPoint() only with coordinates inside the canvas.
  • Use PrintString, PrintInt, PrintFloat, and PrintComplex for small clues, not inside a million-pixel loop.
  • If a plotted map looks many times too bright, make sure only threadIndex == 0 runs the orbit.
  • If an option always reads zero, check that the key passed to Get…Option exactly matches the key declared in Configure().
